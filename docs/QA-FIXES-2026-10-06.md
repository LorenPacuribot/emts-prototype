# QA fixes: Critical and High items (6 Oct 2026)

Fixes for the 17 Critical and High defects in the QA report of 6 October (`Claude outputs/EMTS-Prototype-QA-Report-2026-10-06.md`), plus the `/api/state` header issue the report asked to treat as Critical. The 56 Medium and Low items are not in this change, except C-07 (new leads now show within 10 seconds), which came with C-02.

Checked: `npx tsc --noEmit` clean, `npx vitest run` 69 files and 768 tests passing, `npm run build` passing. Items marked "browser" were also re-run against the dev server with the report's steps.

## Security

| ID | Fix | Test |
| --- | --- | --- |
| C-01 | `/api/website-form` GET and DELETE need a staff session. A POST that reuses a waiting reference keeps the original; it can no longer overwrite it (Supabase: `ignore-duplicates`). | `lib/website-form-route.test.ts`; browser (curl) |
| `/api/state` header | The `X-EMTS-Page` header is client-sent, so access now has two levels. Customer links with a secret token (estimate, paint record) read and save as before, but never see the payment gateway credentials, and a save can't change them. Public marketing pages (`/r`, `/lp`), which anyone can name, read a redacted copy (only the marketing lists; no leads, customers or finance settings; staff names and roles only) and can't save. Their clicks, views and form submissions go through the new `/api/public/marketing`, which applies just that one action on the server. | `lib/state-route.test.ts` (4 new cases) |
| D-01 | `safeNext` refuses control characters, whitespace and backslashes (browsers drop tab and newline, turning `/\t/evil.com` into `//evil.com`), and the result must resolve to this app. | `lib/auth/server.test.ts`; browser |
| D-02 | Every Settings page checks access itself, not only the sidebar. Rule from the live app: `ADMIN_MASTER_DATA` (owner, office manager) for every page; Goals & Profit and Surface Rates use engine calibration (adds senior estimator); the new pages keep their own permission; My Profile is open to all. Others see "You don't have access". | `features/lib/permissions.test.ts`; browser (luis, priya, grace refused; dana, tim allowed) |

## Money and reports
